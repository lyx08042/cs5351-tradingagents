## 1. 背景

上游 TradingAgents v0.7.1（commit `9fa1196fffbcfd9de5146d2dd2869df84ab99838`）是一个多智能体 LLM 交易分析框架，已具备并行分析师、辩论、结构化输出、memory、checkpoint、报告和测试。课程要求团队在**不破坏现有基线**的前提下，增加五个可验证的治理/安全/数据/审计能力（F1–F5），并保持“无真实券商执行”。

核心痛点：

1. LLM 断言可能缺乏证据支撑（F1）。
2. 单次运行成本可能失控且不可计量（F2）。
3. 交易提议缺少确定性、可复现的安全约束（F3）。
4. 数据缺失常被误当作中性信号（F4）。
5. 最终决策缺少不可篡改、可回放的审计与修订链（F5）。

## 2. 决策

采用**分层、默认拒绝**的扩展架构：

- 在 `tradingagents/course/` 下设置五个叶子模块：`evidence`（A）、`budget`（B）、`safety`（C）、`data_quality`（D）、`audit`（E）。
- 叶子模块**不得相互循环导入**；由**共同所有**的薄编排器串联。
- 运行时 AI 保持**咨询性**；安全、预算、数据充分性、审计为**权威性**，可拒绝或 abstain。
- 所有契约 JSON 可序列化，支持离线回放。
- 不连接真实券商。

### 2.1 运行时上下文分层（PROPOSED）

```
identity → constraints → retrieved evidence → conversation → state → task
```

### 2.2 上下文流水线（PROPOSED）

```
dedup → prioritize → budget → compact → assemble
```

### 2.3 计划中的可配置阈值（**非已达成事实**）

| 参数 | 提议值 | 性质 |
|---|---|---|
| `context_token_cap` | **16000 tokens** | 计划中的可配置设计上限 |
| `compaction_threshold` | **12000 tokens** | 计划中的触发压缩阈值 |
| `reinjection` | 压缩后重新注入关键证据 | 计划机制 |

> 上述数字是**设计阈值**，不是性能结论，也未被任何运行验证。

## 3. 备选方案评估

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. 修改上游核心智能体直接内置规则** | 改动集中 | 破坏 BASE-001/002；难撤；等价于整树改造基线 | 拒绝 |
| **B. 单一 `course` 大模块** | 简单 | 无法独立负责；交叉评审失效；易循环依赖 | 拒绝 |
| **C. 五个叶子模块 + 薄编排器** | 职责清晰；可独立测试；支持交叉评审环；默认拒绝易实现 | 需要契约设计 | **采纳（PROPOSED）** |
| **D. 纯提示词约束（不改代码）** | 零代码风险 | 不可验证、不可回放、非确定性 | 拒绝 |

## 4. 理由

- 方案 C 使每个需求有唯一 owner 与唯一锚点（INV），便于 trace 矩阵与负向测试。
- 权威性/咨询性分离确保 LLM 文本不能覆盖由**确定性代码**给出的 fail-closed 判定。
- 既有源码/测试默认受保护、不整树替换；必要时通过窄范围集成编辑（显式 scope + 契约 + 人工批准）接入。
- JSON 契约支持离线回放（F5）与可复核评估。
- 不整树替换上游基线，满足 BASE-001/002。

## 5. 后果

- 增加契约层与编排层维护成本。
- 需要 ADR 记录每一次契约/安全策略变更。
- 需要真实评估集与重复运行来支撑成本/质量目标（当前为临时目标）。

## 6. 重开条件（Reopen）

出现以下任一情形必须重开本 ADR：

1. 教师要求目录布局迁移或不同模块划分。
2. 契约变更影响到 BASE-001（导入/主流程）或 BASE-002（既有测试）。
3. 安全/审计权威性规则需要变更。
4. 评估显示 20% 成本目标与 ≤3 个百分点质量不劣化无法同时满足。
5. 任何真实券商执行需求（**当前明确排除**）。
