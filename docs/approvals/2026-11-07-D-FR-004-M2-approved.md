## 生效的契约澄清（在编码前纳入测试与实现设计）

1. availability 与 sentiment 分开：status 只允许 available / unavailable / unknown；neutral 是有来源数据的语义值，不是第四种 availability。PT-2 应以 status=available 且显式情绪值为 0/neutral 表示。NT-2/NT-4 的 status=neutral 是非法状态；不允许因字符串 neutral 或数字 0 单独推断 available。
2. 明确零值与缺失：字段确实存在且来源有效的数值 0 可有效；字段不存在、None、空内容或缺少探测结果不能被自动补成 0/neutral。原始观察输入结构、字段存在性与来源有效性须先在 contracts.py 和 fixture 中明确定义，不能声称只凭下游标签就能发现上游隐瞒的缺失。
3. M2 默认五个域 news/social/macro/price/fundamentals 全部必需。省略任何必需域、空输入或重复冲突域均不得 proceed；未知域名、未知状态、必要字段缺失同样 fail-closed。放宽关键域集合属于后续策略变更，另行审批。
4. 决策是确定性的：输入不合法、域遗漏或存在 unknown -> review；否则有 unavailable -> abstain；仅全部必需域合法且 available -> proceed。两种拒绝状态都必须显式标记不允许进入后续决策，不得靠自然语言决定是否放行。
5. 日期不能只做任意字符串相等判断：解析合法 ISO 日期，明确分析截止日期；证据发布时间/可用时间不得晚于分析截止日期。较早的有效证据可以使用，不能一律要求证据日期等于分析日期。无法判断日期有效性 -> unknown/review；新鲜度若有阈值，应在契约中明确、使用固定日期 fixture，不能读取当前时间导致测试漂移。
6. 返回 JSON 可序列化的域标签、决定、原因和不足域列表，保留来源/日期信息；留痕持久化仍归 E 模块。本范围不声称已满足端到端审计或已经约束原版运行流程。

上述澄清属于本次批准的测试与实现契约，不要求再停下来请求同一范围的批准。若实际设计需要新增跨模块接口、放宽准入规则或修改受保护路径，必须停止并另提变更。
