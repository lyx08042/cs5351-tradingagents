## 1. 范围与测试数据

分两阶段验证 `FR-001` / `INV-001`。M2 从 A 的公开接口验证分类、证据绑定和失败结果。M3 从编译后的 LangGraph 或课程入口验证实际进入辩论历史和研究经理输入的数据，同时做共享流程回归。关联 `BASE-001`、`BASE-002`、`NFR-002` 与 `NFR-005`。

使用固定分析日期 `2026-09-01` 和仓库固定场景 `EVAL-006`、`EVAL-008`、`EVAL-009`。人工夹具记录原始内容、来源、标的、日期、状态及策略，用固定数据离线重放。证据和模型输出分别注入，确保测试能显式制造错误引用。M3 可用脚本化模型响应代替外部调用，执行真实图、证据校验和下游状态更新。

## 2. M2 独立验证

| 用例 | 输入或条件 | 必须观察到 |
|---|---|---|
| A01 / EVAL-008 | 合法且切题的 MACD 证据，两种日期均为 `2026-08-30`，配置窗口包含该日 | `accept_factual`，输出保留真实 `evidence_ref`。序列化后的引用仍能回到同一来源。 |
| A02 | 一份证据的两种日期等于分析日，另一份比分析日早两天。分别使用两天和一天的新鲜度窗口。 | 同日证据通过。两天窗口接纳边界上的证据，一天窗口拒绝该历史证据。 |
| A03 / EVAL-006 | “MACD 金叉，股价必涨”且无证据；另测相同预测带真实 MACD 引用 | 预测均是 `hypothesis`。无证据的事实部分不能标 `accept_factual`。无法安全拆分的整句不能升级为事实。 |
| A04 | 无引用、空引用、不存在的 ID、其他运行中的 ID、模型自行提供的证据记录 | 弃权或显式降级。输出中不存在未经采集侧登记的有效引用。 |
| A05 / EVAL-009 | `available_as_of` 在未来；另测只有 `published_at` 在未来 | 两种输入都拒绝该证据，保留稳定的未来日期原因，引用该证据的断言不能通过。 |
| A06 | `unavailable`、`unknown`、缺日期、非法日期、非法策略或已过期 | 不产生有证据的强事实断言，报告明确原因。 |
| A07 | 有效 ID，但实际内容指向其他标的、指标、值、单位或期间 | 即使日期和状态都合法，也不能支持该断言。 |
| A08 | 证据索引中同一 ID 的记录相互冲突，或模型返回非法结构 | 不任意选择记录，不把非法响应写成已验证事实。 |
| A09 | 同一输入和配置重复运行 | 状态、原因、可用引用一致。公开结果 JSON 序列化后语义一致。 |

## 4. 运行与证据

在使用 Python 3.13 的项目环境执行。M3 将集成测试纳入离线目录的同一条全量命令。

```bash
.venv/bin/python -m pytest -o testpaths=test/offline test/offline/test_evidence.py -q
.venv/bin/python -m pytest -o testpaths=test/offline test/offline -q
.venv/bin/python -m pytest -q
.venv/bin/python -m ruff check .
.venv/bin/python scripts/check_course.py --root .
git diff --check
git status --short
```

依赖结构审查检查 A 的导入方向、公共入口及受保护文件的 diff。默认 `pytest` 的 `testpaths` 为 `tests/`，课程脚手架 CI 目前只显式运行脚手架测试文件。因此必须单独记录完整 `test/offline/` 的结果，并确认实际 GitHub checks 覆盖哪些项。保存准确命令、退出码、提交、案例/夹具版本、实际通过和跳过数、失败和修复记录。

## 5. 判定标准与语义评估

- **FR-001 / INV-001。** 在固定场景中，M2 的校验输出以及 M3 的实际辩论历史中，无合格证据的强事实断言数均须为 `0`。记录强事实总数、违规数及弃权/假设数。有效历史证据的正向用例必须通过，全部弃权的结果不能证明符合要求。
- **固定集语义。** 提示词或模型变更前固定评估集版本、配置和判分规则。使用现有 0–2 rubric 对照基线与变更后结果，覆盖引用正确性和事实/预测区分。有语义判分时保存样本和依据。记录 `NFR-002` 的质量差值以及相关暂定阈值，离线确定性通过时也单独报告真实模型语义结果的状态。
- **回归与结构。** 上游全量回归、所有课程离线用例、Ruff 和需求/trace 检查均记录真实结果。依赖或评估未能运行时提供可复现的失败信息并标注待验证。进入最终交付前由 E 检查正负向证据，记录实际评审和 CI 状态。
