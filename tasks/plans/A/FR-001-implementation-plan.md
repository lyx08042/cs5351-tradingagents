## 1. 需求、范围和验收

`FR-001` / `INV-001` 要求看多、看空辩论中的强事实断言有至少一个已检索、可用且切题的证据单元。预测始终标为假设。无合格证据或无法可靠分类时，输出假设或弃权。证据的 `published_at` 与 `available_as_of` 均须不晚于该轮分析日期，有效的历史证据依配置判定新鲜度。

正式验收看**实际进入辩论历史和研究经理输入的内容**。固定案例中无合格证据的强事实断言比例须为 `0`，并有合法历史证据被接纳的正向对照。`NFR-002` 的语义质量比较和 `NFR-005` 的模块依赖约束单独记录。证据状态与 D 的 `FR-004` 对齐，引用可供 E 追踪。需求与证据入口见[需求注册表](../../../docs/req/requirements.yaml)及[追踪矩阵](../../../docs/architecture/trace-matrix.md)。

## 2. 接口、证据和失效策略

以下为设计契约。M1 用 ADR 或设计记录固定字段、示例、版本及依赖方向，M2 将实际公开接口同步到文档。

| 数据 | 计划契约 |
|---|---|
| `EvidenceUnit` | `evidence_id`、`source`（`tool` / `report`）、`content_ref`、`published_at`、`available_as_of`、`status`（`available` / `unavailable` / `unknown`）和可配置新鲜度策略标识。输入由本次运行采集侧登记，保留可定位的来源和所支持的事实。 |
| `Claim` | 一条原子断言，关联 `claim_id`、事实或预测分类及 `evidence_refs`。事实使用可比较的主题、事实项及值；涉及单位、周期或日期时一起核对。自由文本或混合断言仅在能安全拆分或规范化时进入事实路径。 |
| 校验输入及输出 | 输入为明确的 `as_of`、策略、只读证据索引与待校验断言。返回逐条状态（`accept_factual` / `hypothesis` / `abstain`）、稳定原因码及通过校验的引用。先做状态和日期校验，再核对引用是否支持该事实。整个过程可离线重放。 |

- **来源边界。** 模型可以引用本次提供的证据 ID，证据目录、日期和状态来自采集侧。只接受能定位回实际工具结果或具备可靠来源的报告内容。ID 存在、报告文字相似或模型自行声称引用，都不足以通过事实校验。首轮演示至少覆盖有可靠来源的市场指标事实，其他事实形态按可验证来源扩展。
- **截止日期与新鲜度。** 使用分析输入 `as_of` 及显式的来源新鲜度配置，同日和窗口内的历史证据均可接纳。日期非法、任一日期晚于 `as_of`、超窗、状态不可用或未知的证据均排除。缺失来源日期视为未知，分析日期或报告生成日不用于填补来源日期。
- **分类与失败。** 预测携带合法引用也只能标记为 `hypothesis`。可分离的事实和预测独立判定，无法安全分类的内容弃权。虚构引用、来源不相干、重复 ID 歧义、异常结构等输入不能产生 `accept_factual`。集成阶段由校验结果生成辩论历史，原始模型文本不进入可被下游当作事实消费的字段。

## 5. 风险、回滚和设计记录

| 风险 | 处理 |
|---|---|
| 上游报告只有自由文本，缺日期或原始引用 | 在 M1 验证实际输入。优先使用有可追踪元数据的来源，缺元数据显式降级。M3 用一个真实图中可接入的正向夹具证明覆盖。 |
| 引用通过但内容不支持断言 | 事实路径严格比对声明与证据支持的事实项。相反值、不同标的、单位和日期不符分别测。对无法比对的来源弃权。 |
| B 与 C/D/E 合并顺序改变接入边界 | 协调 PR 基于最新确定基线，记录提交组合，对预算、D 准入、C 安全、E 审计和 A 接入做回归。 |
| 模型输出变更影响质量或预算 | 先固定案例再改提示词。分别记录确定性测试和语义质量结果。无法执行的实验标为待验证。 |

接口设计记录在 `docs/architecture/adr/`，编号以写入时实际剩余编号为准。M1 记录 A 的证据来源、校验和投影契约，M3 记录共享接入及与 D/B/E 的边界。回滚按独立模块 PR 与协调 PR 分开处理。出现集成回归时先撤回接入变更，保留离线校验器和既有审计历史。
